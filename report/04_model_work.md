# Software Model Development

## Overview

The software model serves two roles in this project. First, it is the source of the trained weights loaded into the hardware — the Python training pipeline produces `.mem` files that are baked into the FPGA bitstream. Second, it is the reference for hardware validation: every hardware module's outputs are compared against the equivalent PyTorch operation to measure quantization error and detect bugs.

The model itself (`model.py`) is a standard PyTorch transformer decoder — a single-layer, decoder-only transformer with multi-head attention, a feed-forward network, and two layer normalization steps. It was provided by the original GenCore repository and required no structural changes.

## Training Data

The original training script trained on 24 hardcoded sentences for 100 epochs. This is far too small a dataset — the model simply memorizes the training set, and any comparison between variants would be statistically meaningless.

To produce a meaningful training set, I built a template-based sentence generator. The vocabulary consists of 40 tokens: articles, animals, verbs, adverbs, adjectives, conjunctions, and special tokens (`start`, `end`, `pad`). Sentences are generated by filling slot templates:

| Template | Example |
|----------|---------|
| `start [article] [animal] [verb] [adverb] end pad pad` | *the cat sleeps gently* |
| `start [article] [adjective] [animal] [verb] [adverb] end pad` | *the blue dog swims slowly* |
| `start [article] [animal] [verb] and [verb] [adverb] end` | *the bird flies and swims quickly* |

The `and` conjunction token was present in the vocabulary (token index 39) but had never appeared in any training sentence. Adding it to a template ensured the model learned a representation for it.

Training on 5,000 generated sentences takes approximately one minute and produces a model that reliably generates valid grammatical sentences. Training on only 500 sentences is sufficient for most tokens but causes edge cases — the `dog` token's embedding shifted outside the hardware's Q8.8 quantization range, causing garbage hardware output for inputs beginning with `the dog`. Increasing to 5,000 sentences resolved this entirely, with final logit correlations of 0.9996 or higher across all test cases.

## Inference Interface

A unified inference interface (`interface.py`) wraps both the PyTorch software model and the hardware backends behind a single API. Given an input token sequence, the interface runs the model forward pass and returns the predicted next token. This design allows the same test and comparison code to run against any backend without modification.

Generation runs autoregressively: the interface feeds the current sequence to the model, appends the predicted token, and repeats until an `end` token is emitted or a token limit is reached. Because the hardware uses deterministic argmax (rather than weighted random sampling from the logit distribution), the same input always produces the same output — which is useful for validation but limits sentence variety.
